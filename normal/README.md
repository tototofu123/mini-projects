# Normal Portfolio — Hiring-Focused Build Brief

The normal portfolio is the primary public link. It should be fast, readable, and effective without experimental interactions. It is a case-study publication, not a visual effects demo.

## Page structure

| Section | Reader takeaway | Required content |
|---|---|---|
| Hero | Toto builds across web, AI, and embedded systems | Name, positioning, selected-work link, showcase link |
| Work index | Six distinct projects prove breadth | One factual card per selected project |
| Case studies | Toto makes technical and product decisions deliberately | Problem, role, architecture, decision, evidence, limit |
| Working style | The portfolio reflects a grounded builder | Short principles and a compact capabilities map |
| Contact | A visitor can start a conversation immediately | Email, GitHub, and clear call to action |

## Visual rules

Use warm paper, graphite, and sparse signal blue. The left marginalia rail anchors identity and navigation while content flows in an asymmetric editorial column. Motion only supports reading: simple reveals, progress cues, and optional image expansion. The interface must be excellent on mobile and completely usable with keyboard navigation.

## Normal portfolio success test

A hiring manager should understand the six-project set, Toto’s role, and the strongest technical evidence in under three minutes—even with images disabled and reduced motion enabled.
